# Feature reference

This is the detailed behavior and implementation reference for Jarvis. For the short pitch, screenshots, install steps and security model, start with the [README](../README.md).

## Detailed features

- Streaming chat from any OpenAI-compatible `/chat/completions` endpoint and from Anthropic `/v1/messages`.
- Local SQLite transcripts with full-text search, inline rename, delete, regenerate and stop.
- Remote MCP over **Streamable HTTP 2026-07-28** (stateless headers, `server/discover`, request-scoped SSE progress, MRTR input), with legacy **2025-11-25** `initialize` fallback, deprecated **HTTP+SSE** fallback, and **OAuth 2.0 + PKCE** for subscription-backed servers such as T3 Code.
- Local MCP servers over **stdio**, including `npx` packages. Add a command, one argument per line, an optional working directory and optional environment variables; Jarvis keeps the child process alive between tool calls and stops it when the server is disabled, edited or deleted.
- The model can call discovered MCP tools inside a normal turn. Tool calls and reasoning are grouped into a collapsible activity summary with the final answer below; detail cards stream live (`queued → running → ok / error`) and run in parallel (max 4). Any text the model emits before a tool call stays in the stored message for context but is not rendered as an interim note — detail cards show only thoughts and tools.
- Per-chat MCP server selection with **lazy catalog + call** delivery. The MCP popover only selects which servers are active; there is no direct-schema mode. A compact server/tool/argument catalog goes in the system prompt, and the model calls `mcp_call_tool` directly (`mcp_get_tool_schema` when the catalog line does not list every argument; `mcp_search_tools` only when the catalog is truncated). `mcp_execute` runs up to 8 independent MCP calls in one step (4 in flight), so a multi-tool answer does not need many model round trips. Approval and policy checks still apply to each real target.
- The model picker sits in the composer footer; the trigger shows only the model name after the final `/`, provider choices show only the provider name, and long model lists are searchable. Next to it, the reasoning-effort picker offers Default, Low, Medium, High, and Max for the current chat. Default sends no extra parameter; OpenAI-compatible providers receive `reasoning_effort`, while Anthropic maps the level to a thinking budget. Export conversation lives in Settings → Export conversation.
- The workspace files panel browses the active conversation's workspace with a lazy, directory-by-directory tree and resizable tree/preview split. Open a text file with line numbers and syntax highlighting, preview PNG/JPEG/GIF/WebP images, or switch a markdown file between source and rendered views. Select a line or range in source view and add a comment; the composer shows the file, line range and comment as context chips that can be edited or removed. On send, Jarvis stores a context part and includes the path, selected preview and comment in the user prompt. Other binary files are not rendered; text reads are capped at 512 KB and image previews at 10 MB.
- The composer accepts up to 6 attachments through the native file picker, by dragging files anywhere onto the chat window, or by pasting an image from the clipboard. Images (PNG/JPEG/GIF/WebP, max 5 MB each) are sent to vision models as native OpenAI/Anthropic image blocks. Text, code, and text-based PDF files are inlined into the user turn (up to 100k characters per file, 200k total); scanned PDFs and other binary files are copied into app data, shown in the transcript, and represented to the model by metadata only. Total attachments are capped at 25 MB. Files are copied and previewed from Rust-owned storage, cleaned up with their conversation, and restored to the composer when a message is reverted.
- Live prompt/completion usage in the composer and a step counter, with automatic token-based compaction using a structured handoff summary, ~15k recent-token retention and a 15%/16k buffer; the compactor reuses the normal system/tool prefix where provider caching applies.
- The transcript loads the latest 80 messages first and lazy-loads older pages when you scroll up; full history and compaction remain in SQLite.
- Workspace hygiene: `.jarvisignore` filters `glob`/`grep`, including last-match-wins negation, default `grep` skips non-text extensions, and `.mcp-chat/artifacts` + `.mcp-chat/tmp` are excluded from searches. When the selected workspace is a git repo, Jarvis adds `**/.mcp-chat/artifacts/` and `**/.mcp-chat/tmp/` to the repo's local `.git/info/exclude`, so runtime output is not committed without changing a tracked `.gitignore`; `.mcp-chat/skills` and `.mcp-chat/AGENTS.md` remain committable. `bash` supports `maxLines` with optional `tail`, while `read_tool_output` supports line-based paging. There is **no default step cap**; an optional per-conversation `max_steps` still supports the old **Continue** flow when explicitly configured.
- The desktop window remembers its size, position and maximized state between launches.
- A per-turn loop guard stops three identical tool calls with identical results, injects a strategy-change prompt, and forces one text-only step. While a turn is active, **Steer** stops the current turn and starts a fresh one with the new user message.
- Tool calls and thoughts show in the transcript as compact one-line rows, all collapsed by default. A tool row previews its main argument and result metadata (for example `Edit src/app.ts +12 −3`, `Patch 3 files +48 −12`, `Bash npm test exit 0`, `Grep … (21 matches)`); a thought row shows only **Thought** and its duration when known. Click a row for the full arguments, result, image or error. `read` rows are the exception: they stay a single line with no Arguments/Result body; when the read returns an image, a small thumbnail is shown and clicking it expands the image. A thin header above the rows keeps the **Used N tools** summary with failed-call count and duration, and can hide the whole list. While reasoning is streaming the header shows **Thinking…**, and a running tool shows its name. Rows are collapsed again after a reload or chat switch.
- `edit`, `apply_patch` and `write` keep their diff after they finish: it is stored on the tool call, and one click on the row opens it directly (no Arguments or Result, no second toggle) with added and removed lines highlighted; a multi-file patch shows every file in one body. A failed call, or one without a diff, keeps the regular Arguments/Result/error view. The approval prompt uses the same diff view. The diff is display-only and is never sent to the model.
- An expanded **Thought** that is still streaming follows its newest text. Scroll up inside it to stop following, and scroll back near the bottom to resume. Only the thought body scrolls, not the transcript.
- Tool routing is enforced, not only prompted. `write` creates new files and refuses to replace an existing one unless `overwrite: true`. `bash` refuses commands that clearly write file contents (redirects to a file, `tee`, `sed -i`, `dd of=`, `Set-Content`/`Out-File`/`Add-Content`/`Clear-Content`/`Tee-Object`, `[IO.File]::Write*`, `New-Item -ItemType File`) unless `allowFileWrites: true`; build, test, git, package-manager and plain file-management commands (`mkdir`, `rm`, `mv`) are not affected. The check is a conservative routing aid, not a security boundary, and both refusals happen before any approval prompt. The approval prompt flags a bash call that sets `allowFileWrites`.
- **`/compact [focus]`** in the composer (or the palette, or `Ctrl/Cmd+Shift+K`) summarizes the older messages to free context. It asks first because it cannot be undone, shows the current context size, and takes an optional focus such as "keep the database decisions". It holds the conversation while it runs, so nothing can be sent meanwhile, and Stop cancels it.
- **Settings > Appearance** has density (comfortable or compact), chat text size (13 to 19 px) and chat width (narrow, default, wide, full). They apply at once and are remembered. The defaults are the original look.
- **Desktop notifications** (Settings > Notifications, on by default) tell you when a reply finishes, fails, or a tool waits for your approval or answer, while Jarvis is in the background or another chat is open. They show only the chat title and what happened, never your messages or commands. Jarvis asks the system for permission when you send a message, never from the background. There is no tray icon yet.
- **Update checks and automatic updates** (Settings > About) compare the running version with the latest public GitHub release. Check on startup is on by default and can be turned off; **Check for updates** runs it manually. On Windows NSIS and Linux AppImage, Jarvis can download, install and relaunch automatically, optionally without asking after the startup check. Linux `.deb` users still get the release notice and manual download link because `.deb` is owned by the system package manager.
- **Auto** in the composer enables approval-free calls for built-in tools in the current chat after a warning. In auto mode, `read`/`grep`/`glob` may also use explicit paths outside the workspace. Without auto mode, those outside reads ask for an explicit per-call approval instead of failing immediately. `write`/`edit`/`apply_patch` inside the workspace follow auto mode, but outside-workspace writes always require an explicit per-call approval and cannot be auto-approved. Destructive shell commands (`rm -rf`, `del`, `Remove-Item -Recurse`, `git reset --hard`, etc.) and patch file deletions still ask for approval; explicit deny policies still win. MCP still evaluates its server policy first; as before, auto mode can relax an MCP `Ask` to `Allow`, while `Deny` remains.
- Built-in local tools available in every chat: `bash`, `python`, `read`, `grep`, `glob`, `edit`, `apply_patch`, `write`, `skill`, `subagent` and `question`. `apply_patch` applies compact multi-file patches (add/update/move/delete) with CRLF-aware, whitespace-tolerant hunk matching, `@@` context anchors and `*** End of File` anchoring; file deletes still require approval even when auto-approve is on, and outside-workspace targets require explicit approval. `edit` replaces one exact string in one existing file, matches files as the model sees them (LF view) and tolerates typographic punctuation and trailing whitespace; use `apply_patch` for multiple hunks or files. File-mutation approval prompts include a unified diff when the target is inside the workspace. `bash` defaults to PowerShell on Windows and `sh` elsewhere; `cmd`/`pwsh`/`bash` remain explicit options. It supports a per-call `cwd`, labelled stdout/stderr and echo detection; PowerShell uses `-EncodedCommand` to avoid nested-quote failures. Absolute workspace paths are normalized (`\\?\`, case and trailing separators) consistently across filesystem tools. File writes stay inside the workspace by default; outside-workspace `write`/`edit`/`apply_patch` targets always require explicit approval. `read`/`grep`/`glob` can use explicit external paths after per-call approval, or without approval in auto mode. `bash`, `edit`, `apply_patch` and `write` ask for approval by default. `python` runs complete source through stdin with UTF-8 environment, a workspace `cwd`, and timeout, avoiding shell quoting. Shell exit codes are part of the command result; a non-zero exit does not by itself mark the tool call as failed. `question` asks the user one or more blocking questions in a dialog and blocks the turn until they answer or decline. `options` are optional: a question with options shows a picker plus a field for a custom answer, and a question without them is a plain text field, so it also works for free-form answers. The model is told to use it only when the answer changes what it does next and the workspace cannot tell it; status updates and explanations belong in the final answer.
- The `subagent` tool launches a focused task in a hidden child conversation with fresh context. The child inherits the parent's workspace, model, reasoning effort, selected MCP servers and step budget (`0` means unlimited), runs the normal tool loop, and returns only its final report. The tool returns immediately; when the child goes idle, Jarvis appends a hidden `<subagent>` report to the parent. It only starts a parent turn if the parent is idle and no real user follow-up was sent after the launch, so background work does not interrupt or race with work in the parent. Pass the returned `sessionID` to send a follow-up. The parent row shows the task, status and an **Open chat** action; arguments and result previews live in the child transcript. Child approval or input prompts appear in the same dialog with a subagent label. A subagent cannot start another subagent (one level).
- Provider models are fetched once in the provider form and saved with the provider; the chat model picker uses that saved list. Model is optional on the provider.
- Approval policies per server (`auto` / `ask` / `deny`), “allow once”, “always allow” rules, rejection with feedback delivered back to the model. The approval dialog previews the exact rule that “Always allow” will save; shell commands use a conservative prefix pattern such as `cat *`, while risky, compound, or unknown commands keep the exact command. Saved rules apply across chats.
- Tool output is capped at 12k characters for the model, 16k for `bash`/`python`, 24k for `read`, and 24k per `read_tool_output` page. The full payload spills to disk and can be paged without re-truncating the stored result.
- Token-based compaction on context overflow, `finish_reason: length` continuations, retries with backoff, interrupted-stream continuation.
- Markdown with code blocks (language label, copy, horizontal scroll), tables, reasoning sections and a strict no-raw-HTML renderer.
- Default system prompt is **Jarvis**, still editable and resettable in Settings.
- The model receives the local day, date, hour and minute (minute precision) stamped on each user message. Time is injected into the user turn, not the system prompt, so the system + tool catalog prefix stays byte-identical. The timestamp is rendered once at send time and stored as a hidden `time` part, so historical user messages stay byte-identical across later requests; the UI never shows that raw marker.
- Hovering a user message shows its local date and time below the bubble. Hovering any user or assistant message reveals **Copy**; assistant Markdown is copied as rendered rich HTML plus rendered plain text, so pasting into Word/Docs keeps headings, bold, lists, tables and code blocks. User messages also show **Revert**, which asks for confirmation, removes that message and everything after it, then puts the original text and attachments back in the composer for editing and resending.
- The system prompt is Jarvis plus non-editable harness/tool rules, a workspace environment block, optional `AGENTS.md` instructions, and a skill catalog. The harness rules tell the model to batch independent reads/searches (up to 4 concurrent), use `mcp_execute` for independent MCP batches, and delegate large self-contained workstreams to subagents without polling. The timestamp stays on the user turn, so the static prefix remains cache-friendly.
- Each conversation has its own workspace, selectable from the composer's **Workspace** chip with a native folder dialog. New chats inherit the current chat's workspace; existing chats fall back to the previous global default or the process directory. File writes and `bash` use the per-chat workspace; read-only tools may read explicit outside paths in auto mode. Optional project instructions are read from `AGENTS.md` in the home config, app data, workspace root, `.mcp-chat`, and `.opencode`, in that order. A `skill` is a directory containing `SKILL.md` under `.mcp-chat/skills/<name>`, `.opencode/skills/<name>`, app-data `skills`, `~/.config/opencode/skills`, or `~/.config/mcp-chat/skills`. The `skill` tool can also read a file or list a subfolder inside the selected skill, but never outside that skill directory. Jarvis bundles `excalidraw`, `spreadsheet`, `docx`, `pdf`, `antigravity-cli`, and `manage-skill`, and seeds them into `~/.config/mcp-chat/skills` at startup. The installer tracks file hashes in `.jarvis-builtins.json`: untouched built-ins are refreshed, while files you edit are left alone. Use `manage-skill` to create or update a global skill without editing the app bundle. The **Skills** page lists the effective catalog with its source and path, a blue dot for enabled skills and a gray dot for disabled ones, and a global toggle for each name. Disabled skills are removed from the prompt and rejected by the `skill` tool; the choice applies to every workspace and every new chat. `spreadsheet` requires Python 3 and `openpyxl`; `docx` requires `python-docx`; `pdf` requires `pypdf`, `reportlab` and `pdfplumber` (plus optional rasterizers/OCR tools); `antigravity-cli` requires `agy` on PATH; Excalidraw link uploads require `cryptography`. The `docx`, `pdf`, `spreadsheet` and `antigravity-cli` skills include an `INSTALL.md` with the exact commands.
- The transcript renders the newest 80 messages first with **Show earlier messages**; conversation lists and the export selector can load older pages, and conversations can be pinned to the top. Settings has a sticky section navigator. The first-run empty state includes a setup checklist for provider, key and optional MCP server. Error toasts stay longer, can be copied, and expose Retry where the action is useful; modals trap and restore focus. Provider/MCP chips show warning dots when a key or connection is missing.
- Providers, keys and MCP servers are managed from the UI. API keys live in the OS keychain; the webview never receives them back.


## Tool loading and context

Use the **Tools** button in the chat header only to choose which MCP servers this conversation may use. Tool delivery is **lazy catalog + call**: the model gets a compact catalog of servers, tool names, short descriptions and argument summaries, plus `mcp_call_tool`, `mcp_get_tool_schema` and `mcp_execute`. It calls one target directly, or batches 2-8 independent targets in a single `mcp_execute` call; it only falls back to `mcp_search_tools` if the catalog was truncated. If the catalog summary does not list every argument, the model must fetch the target schema instead of guessing. Approvals and server policy still apply to every real target.

The composer shows live prompt/completion usage. Compaction is automatic using the thresholds in **Settings → Context management** (keep the most recent ~15k tokens, 15%-of-window buffer with a 16k floor); `/compact` is the manual path. During summarization the transcript shows **Compacting context…**, and if UI event delivery falls behind it reloads the active transcript instead of leaving a half-streamed message stuck.

## Keyboard shortcuts

`Ctrl` on Windows and Linux, `Cmd` on macOS.

| Shortcut | Action |
|---|---|
| `Ctrl/Cmd+Shift+P` | Command palette |
| `Ctrl/Cmd+K` | Search chats; type `>` for the palette |
| `Ctrl/Cmd+N` | New chat |
| `Ctrl/Cmd+Shift+K` | Compact the conversation |
| `Ctrl/Cmd+Shift+M` | Switch model |
| `Ctrl/Cmd+Shift+O` | Switch workspace |
| `Ctrl/Cmd+B` | Toggle the sidebar |
| `Ctrl/Cmd+,` | Settings |
| `Esc` | Stop the current turn from the message box |
| `Ctrl/Cmd+Enter` | Allow the pending tool call once |
| `Ctrl/Cmd+Shift+Enter` | Always allow the pending tool call |
| `Ctrl/Cmd+Backspace` | Reject the pending tool call |
| `Enter` / `Shift+Enter` | Send / newline |

Approval shortcuts never fire while typing in a text field.
